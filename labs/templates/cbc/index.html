CBC bit-flipping: confidentiality without integrity

AES-CBC keeps data secret, but on its own it never checks whether a ciphertext was tampered with. Flip a bit in one ciphertext block, and the next block's decrypted plaintext flips a corresponding bit too — precisely, predictably, and without ever knowing the key. That's an integrity failure, not a confidentiality one: the attacker still can't read anything, but they can rewrite a byte they already know.

Scope of this demo

Uses a fixed, two-block fake session token so the block-to-block relationship stays easy to follow. Use a throwaway random key and IV — never a real one. The point of this lab is the integrity break itself, not the specific field below — that field is only there because it's the standard, widely-used illustration of what the break enables.

The fake session token

Two 16-byte blocks, plaintext, before any encryption:

BlockContentRole
1{{ block1 }}filler — this one absorbs the damage
2{{ block2 }}an authorization field a real app might trust: isadmin=0

In CBC, block 2's decrypted plaintext is D(C2) XOR C1 — the previous block's ciphertext, not anything from the key, feeds directly into it. That's the whole vulnerability in one equation. This particular field is the same one used in Cryptopals Set 2, Challenge 16, a widely-cited teaching exercise for this exact class of bug (CWE-353 feeding into CWE-807) — it's used here for the same reason, not as a claim that this is a complete, ready-to-run exploit against a real system.

1Get a key and IV

AES-128-CBC needs a 16-byte key and a 16-byte IV. Neither needs to be memorized — the IV isn't secret in real systems (it normally travels alongside the ciphertext); only the key does.

2Encrypt the token (this is what "the server" holds the key for)

1. Build the plaintext file:

python3 -c "open('plain.bin','wb').write(b'{{ block1 }}' + b'{{ block2 }}')"

2. Encrypt it with your key and IV:

openssl enc -aes-128-cbc -K <key> -iv <iv> -nopad -in plain.bin -out cipher.bin

The server builds the same plaintext and encrypts it with the key/IV above.

What comes next

Once you have cipher.bin (or click "Build the token now"), the next screen is the attack itself — flipping the isadmin flag using only the ciphertext, no key involved.
