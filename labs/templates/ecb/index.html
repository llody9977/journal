The ECB codebook attack

AES-128-ECB encrypts every 16-byte plaintext block independently — the same block, the same key, always produces the same ciphertext block. That determinism is the entire flaw: if you can get a reference encryption of every possible block under someone's key, you can read their ciphertext back off the reference, without ever touching the key itself.

Scope of this demo

Only printable ASCII is supported (space through ~, 95 characters) — the codebook needs one reference block per possible character, and that only stays practical for a small alphabet. Use a throwaway random key generated below, never a real key or real secret.

1Get a key

AES-128 needs a 16-byte (32 hex character) key. Generate a random one, or paste your own.

This never leaves your browser except when you explicitly ask the server to encrypt something with it (Step 2b / 3b below). For Step 2a / 3a, it's only used locally, in the openssl command you run yourself.

2Build the reference codebook

The codebook is one 16-byte block per printable ASCII character, that character repeated 16 times — encrypted once, under your key. It's the "answer key" the attack looks things up in.

{{ charset }}

1. Download the reference plaintext (public, deterministic — no secret in it):

Download ref-plain.bin

2. Encrypt it with your key from Step 1:

openssl enc -aes-128-ecb -K <your key> -nopad -in ref-plain.bin -out ref-cipher.bin

You'll upload the resulting ref-cipher.bin in Step 4.

The server builds the same reference plaintext, encrypts it with the key above, and hands back ref-cipher.bin for you to download — nothing is kept afterward.

3Encrypt a secret with the same key

Pick a message. It gets encoded the same way as the codebook (one repeated-character block per character) so its ciphertext blocks are directly comparable — that's what makes the lookup in Step 4 a plain byte match instead of real cryptanalysis.

1. Build the encoded plaintext (this Python one-liner applies the same one-block-per-character encoding):

python3 -c "import sys; text = '<your secret>'; sys.stdout.buffer.write(b''.join(c.encode()*16 for c in text))" > secret-plain.bin

2. Encrypt it with the same key as the codebook:

openssl enc -aes-128-ecb -K <your key> -nopad -in secret-plain.bin -out secret.bin

The server encodes your text and encrypts it with the key above, and hands back secret.bin — nothing is kept afterward.

4Deduce the plaintext — the actual attack

This is the part that never sees a key. Upload only the two ciphertexts — ref-cipher.bin and secret.bin — and the lookup does the rest.

What this doesn't cover

Real secrets aren't encoded as one repeated character per block — that structure exists here purely so the block match is visible with nothing more than xxd. The underlying flaw generalizes directly to the classic byte-at-a-time chosen-prefix ECB attack, which recovers unknown plaintext without needing it pre-structured this way. See the Symmetric Mode Attacks page in the journal for the pattern-leak version of this same flaw.
